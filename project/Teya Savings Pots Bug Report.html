Savings Pots amounts remain visible when hiding sensitive values

Bug 01 / 25

Eye toggle does not mask Savings Pots values on Home

Minor Resolved

When the user activates the eye toggle to hide sensitive amounts on the Home screen, the total balance is masked correctly, but the values inside each Savings Pot card remain visible. The privacy toggle should also mask them.

Expected
Savings Pots amounts are masked together with the main balance.
Actual
Savings Pots amounts stay visible while the balance is hidden.

Missing entry point to create a new Savings Pot in the More menu

Bug 02 / 25

"Create new Savings Pot" is missing from the More menu list

Minor Resolved

When the user taps the "More" button, the action list opens without an entry to create a new Savings Pot. This entry point is expected so the user can start the creation flow directly from the menu.

Expected
"Create new Savings Pot" appears as an item in the More menu list.
Actual
The entry point is missing from the list.

Only "3% AER" should be highlighted in the intro headline

Bug 03 / 25

Word "variable" is being highlighted along with "3% AER"

Trivial Resolved

On the Savings Pots intro screen, only the rate "3% AER" should be emphasized in the accent color. Currently the word "variable" is also styled with the accent, which changes the intended visual hierarchy of the headline.

Two loading states appear before the PIN screen

Bug 09 / 25

Confirm → PIN transition shows two consecutive loaders

Major Open

When the user taps "Confirm" to create the Savings Pot, the button first shows a loading state, and immediately after the whole screen shows a second loading state before the PIN input finally appears. It is worth reviewing which requests run at this step so the final transition feels like a single, fluid moment.

Expected
A single, brief loading state between Confirm and the PIN screen.
Actual
Button loader, then a full-screen loader, then the PIN screen — two loading moments back to back.

At the end of the Savings Pot creation flow, the user is asked to enter the PIN, and immediately after a successful entry the PIN screen appears again asking for the same confirmation. The second prompt should not be shown.

Expected

PIN is requested twice in a row before the flow completes.
